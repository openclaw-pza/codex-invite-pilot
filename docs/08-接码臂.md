# 08 · 接码臂

> 让机器有个自己的手机号，还得教它什么时候该换一个。

## 1. 一句话

流程走到需要手机验证时，机器得临时弄到一个能收短信的号码，
等一条短信，从里面把验证码抠出来。

三件事各有各的坑，其中**抠验证码那一步是整条卖钱路径的最后一环**——
抠错一次，买家拿到一个错的码，而一张卡只有一次机会。

## 2. 为什么不能用显而易见的做法

从短信正文里抠 4~8 位数字，显而易见的做法是一行正则：

```js
/\b(\d{4,8})\b/
```

它错在**短信正文里不止一个数字**。真实短信长这样：

> Your code is 582014. It expires in 2026-08-30. Ref #77213.

这一行正则会返回 `2026`——年份。

而且这个错**不会报错**：它返回了一个格式完全正确的四位数，
下游拿去用，失败在最后一步，看起来像是"验证码不对"，
没人会想到是自己抠错了。

## 3. 踩过的坑

### 3.1 免费那条路早就做对了，收钱这条反而裸奔

这个坑最刺眼的地方是：同一个仓库里，**免费送的邮箱那条路**早就有年份过滤和
分段码支持，而**收钱的接码这条路**只有一行裸正则。

原因很普通：邮箱那条路被用得多，问题早就暴露过；接码这条路上游多数时候
只回一串纯数字，所以一直没出事。但数据库里存着完整短信的字段本身就说明——
**它有时候会回完整短信**，那时候年份、订单号、短链里的数字全在正文里。

> **"一直没出事"不等于"不会出事"。**
> 尤其当同一个系统里另一条路径已经踩过同样的坑时，那不是运气，是待爆的雷。

### 3.2 按优先级试三条，不是碰运气

改法是三条规则按优先级来：

| 优先级 | 规则 | 例子 |
|---|---|---|
| 1 | **带提示词的**：「验证码」「code」「OTP」后面紧跟的数字 | `验证码 582014` |
| 2 | **分段码**：被短横、空格或逐位拆开的 | `129-482`、`5 8 3 0 1 4` |
| 3 | 兜底：正文里的独立数字，**但先滤掉像年份的** | `582014` |

第 3 条那个年份过滤是单独一个函数，因为它要被反复用到：

```js
function looksLikeYear(num) {
  return /^(19|20)\d{2}$/.test(num);
}
```

四位数是 4~8 位里最容易撞的长度，而 `19xx`/`20xx` 在短信里出现的频率高得离谱
（有效期、版权行、订单年份）。

### 3.3 换国家救不了，得换号源

有一轮怎么都收不到码：上游接口返回成功、号码也拿到了，
但短信永远停在"等待中"。

第一反应是换个国家试试。换了两个，一样。

真实原因是**号码本身被目标平台静默拉黑了**——低价档的号大多是回收复用的，
在目标平台那边早有记录。这跟国家没关系，跟**号源**有关系。

> 判据：**上游说成功、下游没反应，问题在两者之间的那一层。**
> 在这个例子里，"两者之间"是号码的历史，而那是接口不会告诉你的东西。

### 3.4 便宜档要主动跳过

低价档号被拒的概率高。所以取号时不是"从最便宜的开始"，
而是**给一个价格下限，主动跳过最便宜那几档**。

这件事看起来是在多花钱，实际是在省钱：一次失败要重新走一遍流程、
消耗一次不可再生的名额，那个成本比档位差价高两个数量级。

同时也要有**上限**——出价上限取「预算」和「平台报价」里的小值，
不能拿卡的面额直接当出价，那样遍历到高价档时会买到超出面额的号，
成了亏本卖。

### 3.5 地区名要有自己的规范表

上游返回的地区中文名简繁混杂，还有错译（有个国家被译成了一种化学物质）。

所以本地存一份规范表，查不到才退回上游给的名字——
**名字旧总比列表空白强**，但也不能直接用对方的。

## 4. 代码在哪

`server/heroSms.js`

| 关注点 | 位置 |
|---|---|
| 验证码抽取三条规则 | `CODE_HINT` / `CODE_SPLIT` / `CODE_GROUP` + `looksLikeYear` |
| 取号与档位 | `requestNumber` / `fetchPriceQuotes` |
| 地区列表 | `loadRegions`，中文名查 `data/country-cn.json` |
| 状态轮询 | `getStatus` / `finishNumber` / `cancelNumber` |

配置：

```
HERO_SMS_API_KEY     密钥
HERO_SMS_BASE_URL    上游地址
HERO_SMS_SERVICE     服务码
HERO_SMS_COUNTRY     默认国家
HERO_SMS_PRIORITY    price = 低价优先 / country = 直接取号
HERO_SMS_MAX_PRICE   单次取号价格上限
```

**只读接口和花钱接口要分清**：查余额、查报价是只读的，随便调；
取号会**真的扣费**。测试里凡是碰到取号的，
必须走 mock（见 `test.setup.mjs` 里对上游的拦截）。

> 这条不只是省钱。真调用会让测试结果依赖上游的库存状态——
> 今天有号就绿、明天没号就红，而你什么都没改。
> **测试打第三方线上 API 本身就是缺陷**，详见 [11 部署校验](11-部署校验.md) 的同类讨论。
