# 07 · 邮箱臂

> 让机器有个自己的信箱。

## 1. 一句话

链路里有两个地方非收信不可：**等一封通知信**，和**读一次邮箱验证码**。

难点不在"怎么读邮件"，在**用什么身份读**——
现在主流邮箱服务已经关掉了密码登录这条路。

## 2. 为什么不能用显而易见的做法

显而易见的做法是：拿账号密码连 IMAP 收信。

这条路已经堵死了。实测连上去拿到的能力串里明写着 `LOGINDISABLED`，
可用的认证机制只剩 OAuth2 一种。**拿到账号密码也收不了信。**

既然都要走 OAuth，那就有个选择：继续用 IMAP，还是用对方的 HTTP 接口。

这里选了后者，理由不是"更现代"，是**依赖更少**：
HTTP 接口是纯 HTTPS + JSON，不用引入 IMAP 客户端库。
这个项目的原则是能不加依赖就不加，多一个库就多一块供应链面。

## 3. 踩过的坑

### 3.1 授权范围写死会被拒，而报错看不出原因

拿刷新令牌换访问令牌时要声明授权范围。写死一个具体权限
（比如"读邮件"）会被拒绝，错误码是一串看不出所以然的编号。

原因是：**令牌是别人签发的，它当初申请了哪些权限我们并不知道。**
你声明的范围只要不是它的子集，整个请求就失败。

正确写法是用那个表示"把这个客户端已获授权的一切给我"的特殊范围值。
实测这批令牌实际授予的权限比我们猜的还多。

> 一般规矩：**跟别人签发的凭据打交道时，别假设它的能力边界。**
> 问它有什么，而不是告诉它你要什么。

### 3.2 两条臂必须走同一份下游代码

这个模块存在的原因之一是做对照实验：一次性域名的地址 vs 真实邮箱地址，
哪一种更容易被对方接受。

对照实验成立的前提是**除了被对照的那一项，其他全都一样**。
所以这个模块的接口刻意跟另一条臂做得**完全一致**——同样的字段名、同样的分类函数。
切换只动一个环境变量，**下游代码路径一个字都不变**。

这是上一轮实验的教训换来的：上一轮的对照组用的是旧样本，
而那期间代码路径改过——于是 n=2 实际上是 n=1 加噪声，结论作废。

> **做 A/B 之前先确认 B 和 A 真的只差那一项。** 不然跑出来的结论会误导之后所有决策。

### 3.3 有令牌就别走授权流程

拿到令牌的路有两条：

| 方式 | 耗时 | 副作用 |
|---|---|---|
| 卖家直接给刷新令牌 | 约 0.2 秒，纯 HTTPS | 无 |
| 自己跑一次设备码授权 | 约 150 秒 | **会触发首次登录的强制绑定流程** |

第二条的副作用正是 [04 号池 §3.1](04-号池.md) 那个坑——
绑定的恢复地址十分钟就失效，等于亲手废掉一份库存。

所以有令牌就直接用，没有才退回去跑授权。这个分支不是优化，是风险规避。

### 3.4 令牌文件的路径要能算出来

一台机器上会有很多个账号的令牌。文件名不能用邮箱地址原文——
地址里有 `@` 和点，还可能有大小写差异，不同系统的处理不一样。

做法是**对地址取哈希、截前若干位当文件名**。
两个模块（入库体检和运行时读信）必须用**同一套算法**，
否则体检写进去的令牌，运行时找不到。

这两处的算法一致性是用代码比对验证过的，不是"看起来一样"。

### 3.5 邮件到不了时，先分清是"没投递"还是"我们没读到"

这两种情况的处理完全不同，而表现一模一样：等不到信。

分辨方法是让程序**每分钟汇报信箱里实际有什么**：

```
[+527s] 仍在等待（已等 527s；信箱 4 封：<发件人/标题摘要> / …）
```

有了这行日志，一眼就能看出是"信箱里啥都没有"（投递侧问题）
还是"信来了但我们没认出来"（判据问题）。

没有这行的时候，同一个现象要查很久，而且经常查错方向。

> **等待类逻辑一定要有心跳，而且心跳要报「现在看到了什么」，不是「还在等」。**
> 「还在等」这四个字不携带任何信息。

## 4. 代码在哪

| 文件 | 干什么 |
|---|---|
| `server/outlookMail.js` | 用刷新令牌走 HTTP 接口收信（首选路径） |
| `server/outlookToken.js` | 入库体检：令牌能不能用（[02 判据层](02-判据层.md)） |
| `server/outlookGrant.js` + `webmailOutlook.js` | 没令牌时跑一次设备码授权 |
| `server/mailProvider.js` | 两条臂的切换点，由 `MAIL_PROVIDER` 决定 |
| `server/cloudflareEmail.js` | 另一条臂：一次性域名地址 |
| `server/automationMatch.js` | 从信里认出链接和验证码 |
| `server/mailKind.js` | 发件人白名单与邮件分类 |

切换只动一个环境变量：

```
MAIL_PROVIDER=cloudflare   # 一次性域名地址
MAIL_PROVIDER=outlook      # 真实邮箱
```

**发货格式**（`server/accountLine.js` 负责解析）：

```
邮箱----密码                                 只有密码
邮箱----密码----client_id----refresh_token   带长效令牌
```

解析这一行本身是个判据，它的坑记在
[02 判据层 §3.4](02-判据层.md#34-另外两个判据两种不同的贵法)。

> ⚠️ **发件人白名单只能有一份。** 曾经有两个模块各存了一份白名单，
> 其中一份少了一个发件人域。对方换域名时，一套认得、另一套认不得，
> 表现是"有时候收得到验证码，有时候收不到"。
> 正确做法是一处定义、另一处 import。
