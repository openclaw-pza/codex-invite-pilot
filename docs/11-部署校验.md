## 1. 一句话

部署脚本最危险的失败，不是"报错退出"，是**一路打印成功，而线上跑的还是旧代码**。

这一篇讲怎么让部署脚本对自己诚实。

## 2. 为什么不能用显而易见的做法

显而易见的做法是：每条命令检查返回码，全是 0 就算成功。

它漏掉的是**返回码为 0 但事情没办成**的那一整类，而这一类在部署里特别多：

| 命令返回 0，但…… |
|---|
| 文件传上去了，但服务没重载，跑的还是旧代码 |
| 文件传到了一个不存在的目录，被当成文件名落地了 |
| 服务重启了，但起来就崩，几秒后又死了 |
| 语法检查通过了，但代码引用了一个不存在的变量 |

每一条都是真实发生过的。它们的共同点是：**你验的是"命令执行完了"，
而你想知道的是"东西变了没有"。**

## 3. 踩过的坑

### 3.1 服务不会因为文件变了就重载

最贵的一次：部署脚本跑完，全绿，而服务继续跑着**三个半小时前**的代码。

表现极其误导——自带令牌的账号还是去跑了一遍不需要的授权流程，
看起来像是"令牌功能没生效"，于是去查令牌解析、查数据库、查配置。
真正的原因是那段代码根本没被加载过。

改法是加一条判据：**进程的启动时间必须比文件的修改时间新。**

```
✅ 文件齐  ✅ 服务 active  ✅ 首页 200  ✅ 进程比文件新
```

四条同时成立才算成功。**没看到这四行就是没成功**，不管前面打印了多少"已传"。

而且这条检查要放在**早退路径上也走一遍**——"文件一致所以跳过上传"
不等于"进程不旧"。上一次部署可能就没重启成功。

### 3.2 传文件要按依赖图算，不能扫目录也不能手挑

- **扫目录**会把别的东西也带上去（临时文件、别的项目的残留）
- **手挑**会漏，而且**漏一个文件不会报错**——远端还留着旧版本，
  于是新旧代码混跑，症状千奇百怪

正确做法是从入口出发算依赖图，把真正被引用到的文件列出来。

但这一条有个盲区：**命令行脚本不在依赖图里**。
它们没有被服务端代码 import，算出来的图不包含它们，
于是它们永远不会被自动传上去。

这个坑真实踩过：手工传过一次之后就漂移了，
服务器上跑着旧版解析器，新格式的数据入库时被静默丢掉。

所以依赖图之外要有一份**显式的附加清单**。

### 3.3 语法检查不验引用

有一次重构时整块删除，把两个变量声明一起带走了。

`node --check` 报的是语法 OK——因为它**只验语法不验引用**。
部署脚本一路报"语法 OK"，脚本上线之后一运行就崩。

改法是给命令行脚本补一个真正**启动它一次**的测试。
判据落在"它能跑起来"上，不是"它能被解析"上。

### 3.4 「已存在就跳过」会静默丢数据

批量导入时用了「已存在就整行跳过」的写法。

后果：一批数据里有些是"已存在的账号 + 新增的令牌"，
整行被跳过，令牌静默丢失。而统计输出显示「新入池 1 个」，看着完全正常。

改法是：**已存在的记录只补空字段，不碰已有状态**。

> 一般规矩：**批量写入的"跳过"分支，要么明确报告跳过了什么，要么根本不该跳过。**
> 静默跳过 + 统计只报新增 = 你永远发现不了丢了什么。

### 3.5 静态资源要打包传，不能一个个传

195 个小文件逐个传，就是 195 次连接握手，实测跑不完。

打成一个包走一次连接，秒级完成。

### 3.6 传到不存在的目录会静默变成文件

远端目录不存在时，拷贝命令会**把文件按目标名落地成一个文件**，
而不是报错。之后所有引用那个目录的代码都找不到东西。

所以传之前先确保目录存在，别赌。

## 4. 代码在哪

| 脚本 | 作用 |
|---|---|
| `scripts/deploy.sh` | 售卖站：依赖图 + 附加清单 + 打包上传 + 四条校验 |
| `scripts/deploy-codex-worker.sh` | 执行器：显式文件清单 + 自动重启 + 陈旧检查 |
| `scripts/import-graph.mjs` | 从入口算依赖图 |
| `scripts/stamp-assets.mjs` | 给静态资源打内容哈希（防新页面配旧样式） |
| `scripts/check-prod.mjs` | 线上巡检 |

部署目标**由环境变量提供，没有默认值**：

```bash
export VEND_DEPLOY_KEY=~/.ssh/your-key.pem
export VEND_DEPLOY_HOST=root@your-server
bash scripts/deploy.sh
```

> 为什么不给默认值：默认值会指向**别人的服务器**。
> 缺配置直接报错退出，比带着一个错误的默认值跑起来安全得多。

`deploy-codex-worker.sh` 默认**只比对不写**，要真的推必须显式加 `--yes`。
推完打印远端的版本控制状态——那边也纳入了版本管理，看得见才回得去。

> ⚠️ 远端的应用目录、服务名、环境变量文件路径目前仍写在脚本里
> （见脚本头部注释）。换服务器要一起改。
> 没做成变量是因为那些命令走单引号传给远端 shell，里面还有给**远端**用的
> 命令替换和变量——改成双引号会让本地先展开一遍，
> 而这个坏法是静默的：脚本照跑，但传过去的命令已经不是你写的那条了。

## 5. 这一条不只属于部署

「判据落在产物上」是这套系统里反复出现的同一条规矩：

| 场景 | 错误的判据 | 正确的判据 |
|---|---|---|
| 部署 | 命令返回 0 | 进程比文件新 |
| 点击 | 点击调用成功 | 页面变了 |
| 发消息 | 接口返回 200 | 出现了只有真回答者算得出的串 |
| 令牌体检 | 换到了令牌 | 用它真读了一次数据 |
| 发卡 | 发卡接口成功 | 买家那边真的能用 |

详见 [02 判据层](02-判据层.md)。
